## Changes since Behavior 0.12.0

Behavior **0.13.0** bundles exact **Core 0.15.0** (verifier **0.10.0**).
The ecosystem and Core have independent release versions. The generated header above names
this build's exact commits and formats; the committed Core pin includes the asset digests.

### Models and public authoring

- **StateMachine** owns transitions of an enum field. Transitions can bind additional state
  entities for atomic effects; state bindings select semantic version 3, while unbound machines
  retain version 2 contracts and identities.
- **RequestFlow** generates persistent requests and their creation actions, using StateMachine
  for status transitions. State-bound transitions select RequestFlow 3 / StateMachine 3;
  unbound flows retain the established version 2 contract.
- **Approval** records immutable decisions and exposes approved/rejected/pending predicates.
  It composes over RequestFlow's generated request entity without changing that subject.
- **WorkQueue** adds claim generations, leases, recovery and terminal work transitions, with
  generated work entities, validity rules and ready/expired reads. It governs work state;
  the host schedules work and executes effects. No fairness, ordering or exactly-once physical
  execution is promised. Trusted time, valid genesis and migration continuity remain explicit
  host obligations.
- Model composition resolves generated declarations before authored expressions and checks
  ownership across the final module. Bindings grant no ownership authority. Model receipts
  identify lowering provenance; Core IR remains the sole runtime meaning.
- Public `@command` declarations and `emit` author durable intents directly in Python.
  Commands select the current command profile; the host consumes committed occurrences.

### Core verification and consumer adaptations

- Complete parent snapshots are required by direct evaluation: `facts["universe"]` lists every
  declared entity, including empty types. Invalid parents refuse as
  `INVALID_INPUT` / `INVALID_STATE_SNAPSHOT`. Store evaluation supplies its snapshot.
- Fresh decisions use record 0.8 and complete resulting-state validation. Historical records
  retain their original formats and replay paths; this release does not rewrite them.
- Verifier 0.10.0 fixes Approval query congruence (Core issue #35). The unchanged reference
  Approval's local uniqueness postconditions now prove, and Feature 506 C19 is no longer
  blocked. This does not prove arbitrary Approval modules or all WorkQueue safety claims.
  Local SMT results, structural induction/ownership arguments, tests and host assumptions
  remain distinct. INCONCLUSIVE is unproven.
- Consumers using authenticated verification need policies for the selected verifier version;
  historical evidence is not implicitly upgraded. Required-governance v1 histories require
  explicit adoption into Store v2 for fresh writes. V2 command histories use an explicit policy.
- Custom backends must implement idempotent recovery of equivalent original Store creation
  and reject a different creation. Atomic compare-and-set, replay and durable command intents
  retain Core's contracts. A retry after a conflict reevaluates; recovery after a lost
  acknowledgement resubmits the original bundle.

### Consumer Skills and release scope

The existing authoring, verification and application Skills are updated for Behavior 0.13.0,
with standalone public examples for composition, ownership, Approval verification and a
WorkQueue Store lifecycle. Use Skills from the same release tag as the installed wheel.
Existing package, full conformance and reproducibility checks remain the release process.
Noncritical usability improvements and documentation polish are reserved for later releases.
