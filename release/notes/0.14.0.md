# Behavior 0.14.0 — scalable Safety certification

Development release notes; publication is not part of Feature 511 implementation.

Core remains pinned exactly to 0.15.0, verifier 0.10.0. FieldOwnership and LifecycleDependency
policy semantics remain v1, with unchanged Core behavior, Store state/replay and behavioral Model
receipts. Safety checker 3 changes certification outcomes and evidence contracts, requiring the
minor version under the existing 0.x policy.

Safety evidence and bundle v2 carry typed, untrusted merge-trace data. Consumers independently
prepare the complete expected module/policies, check every obligation with Lean, audit all sixteen
intended root types and allowed transitive axioms, and run fresh kernel replay. Compact proof-only
input reduces incidental representation/code-generation work without accepting a native oracle or
cached prior approval. Proof construction is outside the trusted producer boundary.

Consumers must generate new v2 evidence; this checker does not reinterpret historical v1 bundles.
Published artifacts remain immutable and retain original pinned inspection conditions, subject to
the original implementation's soundness. An incompatible artifact or invalid witness is not a
mathematical counterexample. Initial-state, migration and deployment authorization obligations
remain explicit and separate. No runtime Safety state, Core extension or new Safety language is added.

The final capacity profile and measured limits are recorded with the exact evaluated artifact in
`specs/511-safety-certification-scale`; implementation prototypes are not final release acceptance.
