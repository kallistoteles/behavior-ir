# Implementation Review: Verifiable Behavior IR Core (v0.1)

**Purpose**: Review of the implementation against `PRINCIPLES.md` and the constitution (task T075)
**Date**: 2026-09-23
**Scope**: `crates/`, `python/behavior/`, `tests/fixtures/`, `scripts/`

Each item was checked in the code or by a test, not by reading intent. Evidence is noted.

## PRINCIPLES.md

- [x] §2 Transitions return ΔS before anything changes: `eval::run_transition` computes all
  effects against S, builds `S'` as a copy, and returns `changes` only when every check passes
  (`discount_breaks_invariant` golden: DENY with empty changes).
- [x] §3 Predicates see only their declared inputs: preconditions and postconditions evaluate
  over the action's parameters; invariants over one entity. Permissions are still written as
  preconditions in v0.1 (spec Assumptions); a dedicated permission construct is deferred.
- [x] §4 Effects describe change: `set_` records `(param, field, value)`; nothing executes.
- [x] §5 Behavior is data: the DSL builds trees; `Expr.__bool__` raises (tests in
  `test_dsl.py`: `if`, `not`, chained comparison).
- [x] §6 Content-addressed identity: `admit/hash.rs` implements contracts/hashing.md;
  frozen vectors verified by an independent Python implementation of the contract;
  `hash.rs` never reads `loc`; derived/invariant/action names appear only in module entries
  (`hash_properties.rs`: locations, renames, reordering, implicit vs explicit conversions).
- [x] §8 References explicit, dependencies derived: `admit/graph.rs` builds the graph from
  `derived` nodes; no declared dependencies exist.
- [x] §9 Invalid behavior cannot enter the semantic model: semantic types have `pub(crate)`
  fields and constructors, so no code outside `behavior-core` can build them; the CLI and the
  Python binding always call `admit` before `evaluate`/`replay`/`evaluate_intent`.
  Note: the guarantee is at the crate boundary; inside `behavior-core` only `admit/` builds
  semantic nodes by convention (verified by review, not by the compiler).
- [x] §9 One type checker (revised 2026-09-25): the Python DSL drives the Rust builder, which
  runs `admit/typecheck.rs` on each new node; JSON admission and `Builder::finish` share
  `admit_wire`. The builder produces the same behavior versions as the hand-written wire
  fixtures (`tests/builder.rs`); `typing_cases.json` (85 cases) runs against the engine.
- [x] §11 Transitions preserve validity: invariants run on S before preconditions
  (`invoice_invalid_state` golden: INVALID_STATE, only `invariant_pre` in the trace).
- [x] §13 AI only through capabilities: intents carry capability, targets, input; state and
  context come from the host (`state_supplied`, `extra_field`, `target_mismatch` fixtures).

## Constitution

- [x] I. No AI calls in v0.1; the only AI-facing surface is `evaluate_intent`.
- [x] II. Intents are strictly decoded; every problem is a typed error listed by path.
- [x] III. Tests were written and seen to fail before each implementation phase; golden files
  (hash vectors, wire, versions, records) were generated, then reviewed by hand. Evaluation was
  additionally checked against hand-written expectations (`requests/expectations.json`)
  before any golden record existed.
- [x] IV. No clock, randomness, environment, or `HashMap` in the engine
  (`grep` for `SystemTime|Instant|rand::|std::env|HashMap|HashSet` in engine sources: none);
  outputs are canonical JSON; `scripts/determinism-check.sh` passes.
- [x] V. Every evaluation emits a record with predicate hashes, values read, outcomes, and
  source locations; records replay byte for byte.
- [x] VI. One core crate, a CLI, a binding; deviations recorded in plan.md Complexity Tracking.
- [x] Tech: `#![forbid(unsafe_code)]` in `behavior-core` and `behavior-cli`; no hand-written
  `unsafe` in `behavior-py` (only PyO3 macro expansion); no floats in the engine
  (`grep f64|f32`: only JSON float detection); `unwrap`/`expect` denied by clippy outside tests;
  `Cargo.lock` committed; Rust pinned to 1.98.1.

## Deviations from tasks.md (recorded)

- The CLI `admit`/`version`/`hashes` subcommands and their test (T035, T043) were implemented
  during the foundational phase because the determinism gate (T029) needs them.
- Golden decision records (T049) were generated by the implementation and reviewed, rather
  than typed by hand; hand-written expectations (`requests/expectations.json`) were written
  first and are asserted independently.
- An extra intent fixture `state_supplied` covers spec US3 scenario 5 (an intent supplying
  state is rejected).
- Entity locations use the caller's frame so entities defined outside module files (REPL,
  `exec`, notebooks) work; found while verifying the README example.

## Revision 2026-09-25: Python as a binding (Phase 7)

- [x] One construction path: `Builder::finish` and `admit` both call `admit_wire`; the builder
  checks nodes with `admit::typecheck::check_expr`, not a copy of the rules.
- [x] Only admitted modules serialize (`serialize::to_wire_json` takes `&Module`); round trip
  and idempotence hold for every valid fixture and all 38 hash vectors (`tests/serialize.rs`).
- [x] Regression net unchanged: `versions.json`, `hash_vectors.json`, and every decision record
  are byte-identical; the Python golden wire files changed only by listing declarations by
  name and writing two conversions explicitly (`some(actor.id)`), and they admit to the same
  behavior versions as before.
- [x] Python no longer contains typing rules or JSON emission of behavior; `test_types.py` was
  removed because there is no second checker to compare.
